## 为什么要有这个博客

学过的东西，如果不写下来，过几周就只剩下“我好像在哪儿看过”的印象。

所以这个博客的定位很简单：**把我正在学的东西、踩过的坑、想明白的地方写下来**。不追求篇幅，追求以后自己还能看懂。

## 内容是怎么组织的

Firefly 提供三种归类方式，我用它们的分工是这样的：

- **分类（category）**：一篇文章只能属于一个分类，所以分类用得比较“粗”，就是上面那四个方向加上「写作与站务」。
- **标签（tags）**：具体的技术点，比如 `STM32`、`PyTorch`、`FreeRTOS`，方便横向找同一主题的笔记。
- **系列（series）**：同一门课或同一本书的连续笔记，按 `seriesOrder` 排序。

## 怎么发一篇新文章

在项目目录里执行：

```bash
pnpm new-post 我的新文章
```

然后在 `src/content/posts/` 里找到生成的 Markdown 文件，按下面的字段填写开头部分（Frontmatter）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `published` | 是 | 发布日期，例如 `2026-10-01` |
| `description` | 否 | 摘要，会显示在文章列表和搜索结果里 |
| `category` | 否 | 分类，用一个就够 |
| `tags` | 否 | 标签数组，例如 `[STM32, C语言]` |
| `image` | 否 | 封面图，留空则不显示封面 |
| `pinned` | 否 | 设为 `true` 会置顶 |
| `draft` | 否 | 设为 `true` 就只是草稿，不会发布 |
| `series` / `seriesOrder` | 否 | 系列名和它在系列中的顺序 |
| `password` | 否 | 设置后文章需要密码才能查看 |
| `updated` | 否 | 最后修改日期 |

## 本地预览和发布

```bash
pnpm dev      # 本地起开发服务器，边写边看
pnpm build    # 构建生产版本，检查有没有报错
git push      # 推送到 GitHub，自动发布
```

推送之后，GitHub Actions 会自动构建并发布到 GitHub Pages，站点地址是 <https://blog.abitofbroom.390831000.xyz/>。

> [!NOTE]
> 写文章时不用记这些命令，记住一条就够了：**写完先 `pnpm dev` 看一眼，再 `git push`**。
