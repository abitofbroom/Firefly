**一.计算机的思维方式总结：枚举比找公式更自然**

- **核心认知**：计算机天生适合“一个一个试”，而不是像人类那样找捷径或套公式。
- 写代码时，优先考虑 **穷举（枚举）** 思路，往往比推导数学公式更容易转化为程序。
- **体悟**：刚开始写代码总觉得要“聪明地”解决问题，后来才发现，让计算机暴力枚举反而更快实现——因为我们觉得“笨”的方法，计算机执行起来飞快，而且代码逻辑更清晰。这正是算法优化的起点：先跑通，再优化。

.**二.想法 → 程序(代码)→ 程序(汇编语言)→ 计算机执行**

| 步骤                     | 说明                                             |
| :----------------------- | :----------------------------------------------- |
| ① 想法 → 程序（代码）    | 程序员用 C/Python 等高级语言写出人类可读的源代码 |
| ② 程序（代码）→ 机器指令 | 编译器/解释器将源码转化为 CPU 能执行的二进制指令 |

*1*.解释执行:

    程序由一个能看懂代码的程序一边看一边执行; 如果再次执行, 仍然需要解释才能执行

*2*.编译执行:

    程序先由一个能看懂代码的程序编译成计算机看的懂的语言, 然后让这串语言被执行; 如果再次执行, 可直接执行该串语言

**三.打印与输入**

*1*.printf 语法: 在内容处输入想要打印出来的内容---部分特殊符号%d 处会被括号外的数字替代,\n 表示前面内容输入完毕后换行

```cpp
printf("内容");                // 直接打印字符串
printf("内容%d\n", 数值);      // %d 处被括号外的数值替换，\n 表示换行
```

*2*.scanf 语法: 先创建一个变量(记得初始化), scanf 后紧跟这个要被赋值的变量

```cpp
int price = 0;              // 创建整型变量并初始化
scanf("%d", &price);        // 从键盘读取整数，赋值给 price
// 注:&表示取地址符,这里的输入是直接修改指针对应的数据,可以避免声明未初始化就使用变量的影响
printf("%d", price - 10);   // 输出 price - 10 的结果
```

**四.四则运算(单目是运算符)**

| 名称 | 符号(运算) | 符号(代码) |
| ---- | :--------- | :--------- |
| 加法 | +          | +          |
| 减法 | -          | -          |
| 乘法 | ×          | *          |
| 除法 | ÷          | /          |
| 取余 |            | %          |

```cpp
printf("1+4=%d\n", 1+4);    // 输出: 1+4=5
printf("1-4=%d\n", 1-4);    // 输出: 1-4=-3
printf("1*4=%d\n", 1*4);    // 输出: 1*4=4
printf("4/2=%d\n", 4/2);    // 输出: 4/2=2
printf("4%%2=%d\n", 4%2);   // 输出: 4%2=0
```

**六、学习体悟：从“看不懂”到“有点感觉”**

1. **关于 `%d` 和 `&` 的初印象**：
   刚开始觉得这些符号好奇怪，为什么要用 `%d` 而不是直接写数字？为什么要加 `&` 才能输入？后来理解了“占位”和“地址”的概念，才算真正迈过门槛。
2. **计算机的“笨”与“快”**：
   第一次理解枚举思维时有点触动——计算机不是靠“聪明”解决问题，而是靠“耐心”和“速度”。很多时候我绞尽脑汁想的公式，不如写一个循环让它一个个试。
3. **编译 vs 解释的类比**：
   编译执行像是“一次翻译，多次阅读”，解释执行像是“边看边翻”。这个类比让我很快记住了两者的区别。
