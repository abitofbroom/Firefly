## 工程概览

> 工程：`keil_project/9-2 LED点阵屏显示动画`，芯片 STC89C52RC，Keil C51（PK51 9.60）。
> 编译结果：`data=12.0 xdata=0 code=354`，0 错误 0 警告。

### 硬件连接

| 信号 | 引脚 | 说明 |
| --- | --- | --- |
| SER | P3^4 | 74HC595 串行数据输入 |
| SCK（SRCLK） | P3^6 | **移位**时钟：每个上升沿把 SER 上的 1 位移入 |
| RCK（RCLK） | P3^5 | **锁存**时钟：一个脉冲把 8 位移位寄存器搬到输出寄存器 |
| P0 | P0.0~P0.7 | 列选（8 列），低电平选中 |
| P2 | P2.0~P2.7 | 工程里多写了一行 `P2 = ~Byte`，见「待确认」 |

8×8 点阵屏有 16 个引脚 = 8 行 + 8 列。直接接单片机要 16 个 IO，所以用 **74HC595（串入并出）**：只需 SER / SCK / RCK 三根线就能把 8 位数据串行送进去，省下 5 个 IO。

### 74HC595 的写入时序

```c
void _74HC595_WriteByte(unsigned char Byte)
{
	unsigned char i;
	for(i = 0; i < 8; i++)
	{
		SER = Byte & (0x80 >> i);   // 从最高位开始逐位取出
		SCK = 1;                    // 上升沿：移入一位
		SCK = 0;
	}
	RCK = 1;                        // 上升沿：8 位一起锁存到输出口
	RCK = 0;
	P2 = ~Byte;                     // 见「待确认」
}
```

- **串行移位 → 并行输出**：先一位一位打进移位寄存器，最后用 RCK 一次性锁存。移位过程中输出不变，所以屏幕上不会出现中间态闪烁。
- **`Byte & (0x80 >> i)`**：`0x80` = `1000 0000`，右移 i 位得到 `0100 0000`、`0010 0000`……再与 Byte 相与就取出第 i 位，即**高位先发**。这是 595 和字模的通用约定。
- **SCK 与 RCK 别混**：SCK/SRCLK 是"移位"时钟（每来一位敲一下），RCK/RCLK 是"锁存"时钟（8 位送完敲一下）。写反了会只亮一位或整屏乱码。
- 595 另外两根脚 OE（输出使能，要拉低）和 SRCLR（移位寄存器清零，要拉高）一般由开发板硬接线，代码里不用管。

### 显示一列：列扫描 + 消影

```c
void MatrixLED_ShowColumn(unsigned char Column, Data)
{
	_74HC595_WriteByte(Data);       // 送这一列的 8 行数据
	P0 = ~(0x80 >> Column);         // 选中第 Column 列（低电平有效）
	Delay(1);                       // 停留 1ms
	P0 = 0xFF;                      // 关掉所有列 -> 消影
}
```

- **扫描原理**：一次只点亮一列（8 个 LED），8 列轮流快速显示，靠视觉暂留看起来是同时亮的——就是 10.16 说的"段选位选交替"。
- **极性要取反**：`P0 = ~(0x80 >> Column)`、`P2 = ~Byte` 都是"低电平有效"，因为板上行列经过反相/三极管驱动。换开发板要按原理图改极性。
- **消影必须写**：`P0 = 0xFF` 在换列前把所有列关掉。少了这句，上一列的余像会拖到下一列，出现重影/串位（和数码管消影同一个道理）。
- **`Delay(1)` 同时决定亮度和刷新率**：8 列 × 1ms = 8ms 扫一屏 ≈ 125Hz，远高于人眼闪烁阈值（约 60Hz）；延时调大更亮但刷新率下降，太大能看到闪。

### 字模与 `code` 关键字

```c
unsigned char code Animation[] = {
	0x3C,0x42,0xA9,0x85,0x85,0xA9,0x42,0x3C,	//笑脸
	0x3C,0x42,0xA5,0x89,0x89,0xA5,0x42,0x3C,	//哭脸
};
```

- **一个字模 = 8 字节 = 8 列**；每字节的 8 位 = 该列的 8 行，**1 亮 0 灭**（`ShowColumn` 注释写的高位在上）。
- 例：笑脸第一列 `0x3C` = `0011 1100`，只有中间 4 行亮，正是脸的左轮廓。
- **`code` 必须加**：它把数组放进 Flash 的 code 段，不占 RAM。8051 标准片内 RAM 只有 128 字节（STC89C52 多一些，512 字节），字模这类大数组很容易撑爆。本工程 `data=12.0`、`code=354` 说明字模全在 code 段。
- 取模可用 PCtoLCD2002：选"逐列式、逆向、高位在前"。

### 动画：偏移 + 取模回绕

```c
for(i = 0; i < 8; i++)
	MatrixLED_ShowColumn(i, Animation[(i + Offset) % 16]);
```

- 把 `Animation[]` 看成一条**长条纸带**，`Offset` 是显示窗口的左边界，第 i 列取纸带上第 `i+Offset` 个字节。
- **`% 16` 负责回绕**：越界后从头再来，形成循环。数组现在 16 字节（2 帧），所以 `%16`；若启用注释里的 Hello 模（32 字节）必须改成 `%32`。
- **`Offset += 8` 是整帧切换，不是平滑滚动**：一次跳 8 列，画面从笑脸直接变哭脸。要**逐列滚动**就改成 `Offset += 1`。
- **`Count > 100` 是帧率控制**：每扫 100 屏换一帧，100 × 8ms ≈ 0.8s 一帧。改小换帧更快。
- 注释掉的 `if(Offset > 24) Offset = 0;` 现在用不上——`%16` 已经自动回绕。

### 一句话记住

点阵屏 = **行列驱动 + 逐列扫描 + 消影 + 字模**；595 解决"IO 不够"；`code` 解决"RAM 不够"；`Offset + %` 解决"动画"。

### 待确认 / 易错点

1. **`P2 = ~Byte` 这一行**：写完 595 后又把同样的数据取反写到 P2。若板上行数据不走 595 而走 P2，它才必要；否则多余（还多占时序）。要按原理图确认。
2. **`MatrixLED_ShowColumn(unsigned char Column, Data)`**：第二个参数漏了类型，C51 会按 `int` 传参（多占字节、效率低），规范写法是 `unsigned char Data`。
3. `Animation[(i+Offset)%16]` 里的 `16` 和数组长度是**硬编码耦合**，加帧减帧要同步改。
4. 觉得"跳帧"就是 `Offset += 8` 与 `+= 1` 的区别。
